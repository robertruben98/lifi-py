    lifi_py

    lifi-py: a Python client for the LI.FI API (bridge + DEX aggregator).

    RateLimit dataclass

    Snapshot of the API's rate-limit headers from the last response.

    AsyncLifiClient

    Asynchronous client for the LI.FI API.

    A coroutine-based mirror of :class:LifiClient with identical endpoints, parameters and return types. Use it as an async context manager so the underlying HTTP connections are closed on exit.

    The API key is optional (it only raises rate limits); all endpoints work keyless. The client tracks the ratelimit-* response headers, pauses proactively when the quota is exhausted, and retries 429s with backoff.

    Example

    import asyncio async def main(): ... async with AsyncLifiClient() as client: ... return await client.get_chains() chains = asyncio.run(main()) # doctest: +SKIP

    rate_limit property

    The most recent rate-limit snapshot, or None before any call.

    LifiError

    Bases: Exception

    Base class for all errors raised by this library.

    Catch this to handle any lifi-py-originated failure regardless of kind. Note that low-level transport failures (timeouts, connection errors) propagate as the underlying :class:httpx.HTTPError subclasses, not as LifiError.

    Route

    Bases: _Model

    A candidate route returned by POST /advanced/routes.

    Unlike :class:Quote, a route does not include calldata up front; fetch it per step via get_step_transaction (POST /advanced/stepTransaction).

    Status

    Bases: _Model

    Result of GET /status while tracking a cross-chain transfer.

    :attr:status is one of NOT_FOUND, PENDING, DONE or FAILED (INVALID may also appear). Use :attr:is_done, :attr:is_failed and :attr:is_terminal instead of comparing strings.

    is_done property

    True when the transfer completed successfully (status == "DONE").

    is_failed property

    True when the transfer failed (status is FAILED or INVALID).

    is_terminal property

    True once the transfer reached a final state and won't change.

    Step

    Bases: _Model

    One executable step of a route (a bridge or a swap).

    A simple transfer has a single step; complex routes chain several. After fetching calldata (POST /advanced/stepTransaction) the step carries a populated :attr:transaction_request.

    Token

    Bases: _Model

    An ERC-20 (or native) token on a specific chain.

    Token amounts elsewhere in the API are expressed as integer strings in this token's smallest unit (i.e. scaled by 10 ** decimals).

    Tool

    Bases: _Model

    A bridge or exchange integrated by LI.FI (entry in GET /tools).

    ToolDetails

    Bases: _Model

    Identifying details of the tool selected for a quote or step.

    TransactionRequest

    Bases: _Model

    A ready-to-sign EVM transaction returned by /quote or step assembly.

    Numeric fields arrive as hex strings (0x...) as produced by the API; use :meth:as_web3_tx to obtain a dict with those fields decoded to int and keys renamed for web3.py.

    as_web3_tx()

    Return a dict shaped for web3.eth.send_transaction / signing.

    Hex-encoded numeric fields (value, gasLimit, gasPrice) are decoded to int and gasLimit is renamed to gas; to/data are passed through unchanged. Only fields that are set are included, so you can merge in your own nonce/from before signing.

    Returns:
